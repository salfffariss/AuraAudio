# AuraAudio v2.0.2: Safe Managed FLAC Decoder & Forensic Accuracy Fixes

> **Release Type:** Bug-Fix Release (`v2.0.2`)

AuraAudio v2.0.2 is a targeted stability and forensic-accuracy bug-fix release on top of v2.0.1. It replaces the unmaintained `unsafe` `BunLabs.NAudio.Flac` decoder with a pure-managed RFC 9639 FLAC decoder (`0` process-killing access violations across all tested corpora), fixes bit-exact decoding on non-standard bit depths and ID3v2-prefixed FLACs, and resolves concrete false-accusation, mislabeling, and blind-spot issues in `NyquistSpectrumAnalyzer.cs`.

---

## Fixed

- **Process-Killing FLAC Decoder Crashes (`CRITICAL #1`):** Replaced `BunLabs.NAudio.Flac` (`unsafe` `Int32*` pointer arithmetic) with a 100% pure-managed, zero-`unsafe` RFC 9639 decoder (`Audio/Flac/SafeFlacDecoder.cs` and `Audio/Flac/SafeFlacWaveStream.cs`, MIT-derived from `SimpleFlac` / Project Nayuki). All **13 crashing `.flac` files** uncovered in the 263-file external GitHub/IETF corpus (`11` in the initial audit plus `2` exposed under full-stream decode) now fail cleanly with catchable managed exceptions (`13 -> 0` fatal `0xC0000005` crashes; `0` hangs/timeouts). Bounded stream and header validation also reduced the `ietf/faulty/09` (`blocksize 1`) decode stall from `9.2 s` to `3 ms`.
- **Silent PCM Decoding Error & Last-Frame Truncation:** Fixed 64-bit LPC accumulation and trailing partial-frame handling. Resolved `4` canonical STREAMINFO MD5 mismatches in the IETF `subset` suite (`56/60 -> 64/64` MD5 match) and fixed **one silent 24-bit / 48 kHz PCM decoding error found in a real library file** (`260/261 -> 261/261` library PCM MD5 match). Across five representative real music tracks (`16/44.1` through `24/192`), full-stream decode throughput is `1.45x–2.26x` faster (`-31.0%` to `-55.8%`) than v2.0.1 with live CRC checks enabled.
- **ID3v2-Prefixed FLAC Files (`CRITICAL #2a`):** `SafeFlacDecoder` now skips valid leading ID3v2 tags (synchsafe 28-bit size validation, optional ID3v2.4 footer, stacked tags, and bounded zero padding) before the `fLaC` marker. All `5/5` complete ID3v2-prefixed FLAC files in the corpus decode bit-exact (`5/5` MD5 match) while `AudioMetadataReader` tag reading continues to work; `2/2` truncated/fuzzed ID3v2 fixtures fail cleanly with managed exceptions.
- **Non-Standard Bit Depths & Rice Escape Code 0 (`CRITICAL #2b`):** Added MSB-aligned full-scale PCM scaling for `8`, `12`, `15`, `20`, and `32-bit` integer FLAC streams (eliminating silent `-160 dBFS` output on `8-bit` and `32-bit` FLACs) and implemented RFC 9639 Rice escape code `0`. All tested non-standard bit-depth files match canonical STREAMINFO MD5 and `ffmpeg` reference PCM bit-for-bit.
- **Library Scan, Playback & Inspector Resilience:** `LibraryScanner` logs unreadable files via `Trace.TraceWarning`, tracks `ScanProgress.Failed`, skips bad files, and continues scanning. `AudiophilePlaybackController` exposes `PlaybackFailed` (surfaced by `MainViewModel` without closing the app), and the Audio Inspector displays a managed error message when a file cannot be analyzed.
- **False Accusations on Sample Rates `< 44.1 kHz` (`FORENSIC #4`):** Added a dedicated Nyquist-relative analysis branch (`92%` full-band / `85%` early-lossy ratios) and updated Indonesian and English verdict text and badges to print the actual sample rate instead of hardcoded `"44.1 kHz"` or `"CD Quality"`. Eliminated false `SuspectedUpscaledLossy` accusations on `ietf/subset/19` (`35.5 kHz`), `ietf/subset/20` (`39.0 kHz`), and all low-sample-rate genuine ground-truth tracks (`0` false accusations).
- **False `HybridMaster` on Genuine 24-bit / 96 kHz (`FORENSIC #5`):** `HybridMaster` now requires verified evidence of a CD-boundary notch (`p20k - p22.5k >= 12 dB` with steep CD transition slope or CD cliff) combined with ultrasonic rebound above `35 kHz` (`>= 6 dB` above `p22.5k`, either simultaneously or via time-spliced P90 multi-segment envelope), evaluated ahead of `UpscaledFromCd`. Eliminated false `HybridMaster` mislabels on `ietf/subset/28–32, 37` and genuine 24/96 tracks while firing reliably on both synthetic simultaneous-notch and time-spliced hybrid masters.
- **Clean `16/44.1` `soxr` Anti-Aliasing & Short-Clip `< 10 s` Accuracy (`FORENSIC #7.2`, `#7.3`):** Narrowed the 44.1 kHz steep-drop `Inconclusive` guard to `<= 21,250 Hz` so standard `~21.4 kHz` resampler anti-aliasing transitions classify as `VerifiedLossless` (`ietf/subset/11–13, 15–18` and genuine `soxr` downsamples). Short clips (`< 10 s`) now spread 32 FFT windows evenly across 8 segments (halving `< 10 s` DEV window-perturbation flip rate from `5.1%` to `2.6%`) alongside an apples-to-apples `-48 dB` P90 multi-segment consistency guard.
- **New `UpscaledHiRes` Verdict (`FORENSIC #6`):** Added `AuthenticityVerdict.UpscaledHiRes` (`VerdictCategory = "Caution"`, bilingual badges and explanations) to detect Hi-Res containers (`>= 88.2 kHz`) upsampled from lower standard sample rates (`48 / 88.2 / 96 / 176.4 / 192 kHz`, up to `85%` of container rate) using four physical gates including container-aware dead-silence upper bands. Caught `6/6` (`4/4` DEV, `2/2` HOLDOUT) ground-truth Hi-Res upsamples and `ietf/subset/36` (`384 kHz` from `192 kHz`) with `0` false positives.
- **MP3-in-FLAC & `48 kHz` Linear-Mirror Fixes (`FORENSIC #3`, `#7.1`):** Prioritized lossy brickwall detection ahead of `UpscaledFromCd` (`24/96` MP3 transcodes no longer mislabeled as CD upsamples), added container-aware 16-bit quantization floors (`<= -132 dBFS`, `σ <= 2.2 dB`) in `ComputeDeadZeroLossyBrickwall`, replaced single-bin knee lookups with 5-bin local linear-power averaging, and extended `isFlatBroadbandMirror` to `48 kHz` (`6/6` DEV linear mirrors safely held in `Inconclusive`).
- **Inconsistent ALAC Bit Depth, File Bitrate, `IsHiRes` & Number Formatting (`Audio/AudioSourceFormatResolver.cs`):** Replaced split TagLib# vs. decoder format metadata with a single source of truth that parses MP4 `ALACSpecificConfig` (`bitDepth`, `sampleRate`, `numChannels`), MP4 `esds` (`AudioSpecificConfig`), FLAC `STREAMINFO`, and DSF `fmt ` headers directly. Eliminates false `16-bit` readings on 24-bit ALAC files, `48 kHz` caps on 96/192 kHz ALAC/AAC, `44.1 kHz / Stereo` clamping on low-sample-rate or mono files, `0 kbps` ALAC/Opus library entries, and uncompressed PCM bitrates masquerading as file bitrates in the Signal Chain and Inspector. Uncompressed PCM rate in Signal Chain Decompression is now explicitly labeled (`PCM 2,304 kbps`), SQLite and `AudioStreamSpec.IsHiRes` use one lossless-only predicate, and kHz/kbps formatting (`48.0 kHz`, `2,004 kbps`) is consistent across every UI surface and locale.
- **Crash on Clicking Inline Text (`UI/Helpers/TreeNavigationHelper.cs`):** Migrated all 22 `VisualTreeHelper.GetParent` call sites across the UI layer to a shared parent-traversal helper that handles `ContentElement` (`Run`, `Hyperlink`, `Inline`) via `ContentOperations.GetParent` and `LogicalTreeHelper.GetParent`, eliminating unhandled `InvalidOperationException` crashes when clicking text in Inspector explanations, Settings, Info Sheet, or Lyrics.
- **Inspector Track Synchronization (`UI/ViewModels/InspectorViewModel.cs`, `Audio/Controller/IPlaybackTrackSource.cs`):** Connected `InspectorViewModel` to the active playback track source with generation-guarded cancellation so switching tracks from any page immediately updates the Inspector and discards stale results from cancelled analyses.
- **Audio Render Stability, Isolated Forensic Worker & Crash Silencing (`ForensicAnalysisCoordinator.cs`, `GaplessStreamQueue.cs`, `SafeFlacWaveStream.cs`, `WasapiExclusivePlayer.cs`, `App.xaml.cs`):** Serialized forensic analyses onto a dedicated `BelowNormal` worker thread (`<= 1` concurrent analysis), pooled FFT/PCM buffers (`-97.0%` per-call allocation, `0` Gen2 GC under rapid spam), removed hidden background analysis on track switches, made playback seek/position reads non-blocking with zero-allocation in-place fades, elevated the WASAPI render thread (`ThreadPriority.Highest` + MMCSS `"Pro Audio"`), and wired `EmergencyAudioSilencer` into unhandled exception and process-exit hooks to silence active output before teardown.
- **Maximized Floating-Dock Bottom Bleed & Clear Library UI State (`UI/Tokens/NeutralTokens.xaml`, `MainWindow.xaml`, `MainWindow.xaml.cs`, `SettingsViewModel.cs`, `MainViewModel.cs`):** Added a pure-neutral backdrop mask (`Brush.Overlay.DockBottomMask`) behind `FloatingDockCapsule` so scrolled album artwork no longer bleeds beneath its 16 px bottom margin, reduced the Windows auto-hide taskbar trigger gap from `2 px` to `1 px`, passed `MainWindow` as owner to the Clear Library confirmation dialog, and refreshed or cleared stale Album/Artist/Playlist detail views after database clears or rescan deletions.
- **Deleted/Excluded Files Persisting After Library Rescan (`Database/DatabaseManager.cs`, `Scanner/LibraryScanner.cs`, `Scanner/ScanProgress.cs`, `SettingsViewModel.cs`):** `LibraryScanner` now prunes database entries whose physical files were deleted or excluded during rescan (with directory-prefix isolation and removable-drive readiness checks), cascades playlist/artist/history rows, synchronizes `playlists.track_count`, invalidates cached extended track metadata, and surfaces removed counts in Settings scan status.

## Behavior Changes

- **Strict RFC 9639 Decoding & CRC Checks:** `SafeFlacDecoder` verifies frame-header CRC-8, frame-footer CRC-16, and metadata block integrity on every frame. Some corrupted or malformed files that `BunLabs.NAudio.Flac` previously decoded into invalid PCM (`19` corrupt/fuzzed fixtures in the external corpus, including `ietf/faulty/*`, `claxon/fuzz/*`, and malformed metadata fixtures) are now rejected cleanly with managed exceptions instead of playing garbage audio.
- **Mid-Stream Format Changes Unsupported:** Non-subset FLAC streams that change sample rate, channel count, or bit depth mid-stream (`ietf/uncommon/01–04`) are rejected cleanly with `NotSupportedException` rather than playing at wrong pitch or channel layout (WASAPI and NAudio `WaveStream` require a fixed `WaveFormat`).
- **Mid-Stream Frame Corruption Behavior (Playback):** If a FLAC file has a valid header and frame 0 but encounters a CRC or bitstream error in a later frame during playback, decoding raises `InvalidDataException` and playback performs a clean hard stop (no crash, no frame skip or silence fill). Mid-track error reporting and optional frame-resync handling are tracked for a future release.
- **Borderline Verdict Changes vs. `v2.0.1`:** Because v2.0.2 introduces sample-accurate `SEEKTABLE` seeking, 5-bin knee smoothing, stricter `HybridMaster` gating, 44.1 kHz anti-alias handling, and 48 kHz broadband mirror guards, borderline tracks can receive different verdicts than in v2.0.1. Verdicts are computed on demand and are not stored in SQLite, so no database migration or cache invalidation is required.
  - **Aggregate 300-Track Real FLAC Library Sample (`v2.0.1` -> `v2.0.2`, `300/300` OK, `0` crashes, `261/261` MD5 match):** `275/300` (**91.7%**) unchanged; `25/300` (**8.3%**) changed.
  - **Per-Verdict Aggregate Totals (`v2.0.1` -> `v2.0.2`):** `VerifiedLossless`: `91 -> 94 (+3)`, `AcousticNaturalRollOff`: `93 -> 89 (-4)`, `Inconclusive`: `66 -> 70 (+4)`, `UpscaledFromCd`: `41 -> 41 (0)`, `ZeroPadded24Bit`: `5 -> 5 (0)`, `HybridMaster`: `3 -> 1 (-2)`, `SuspectedUpscaledLossy`: `1 -> 0 (-1)`, `UpscaledHiRes`: `0 -> 0 (0)`.
  - **Aggregate Verdict Transitions (`25` tracks total):** `AcousticNaturalRollOff -> Inconclusive` (`6`), `Inconclusive -> VerifiedLossless` (`6`), `VerifiedLossless -> Inconclusive` (`5`), `HybridMaster -> VerifiedLossless` (`2`), `HybridMaster -> Inconclusive` (`1`), `Inconclusive -> AcousticNaturalRollOff` (`1`), `Inconclusive -> UpscaledFromCd` (`1`), `SuspectedUpscaledLossy -> VerifiedLossless` (`1`), `UpscaledFromCd -> HybridMaster` (`1`), `VerifiedLossless -> AcousticNaturalRollOff` (`1`).

## Benchmark Summary & Evidence Scope

To prevent threshold overfitting, the 179-file FFmpeg real-encoder ground-truth matrix was derived from **6 open-source source masters** and frozen by source master before any source edits: **DEV (`100` files: `ietf96`, `elec44`, `studio48`)** for development, and **HOLDOUT (`79` files: `piano96`, `pink44`, `mewkiz192`)** evaluated **once** after code freeze with zero tuning against HOLDOUT.

- **Important Evidence Framing:** Because the ground-truth matrix is built from 6 masters, MP3 detection improvements (`17/33 -> 28/33` `SuspectedUpscaledLossy`) were observed on the **DEV** masters (`elec44`, `studio48`, `ietf96`). On the unseen **HOLDOUT** masters (`piano96`, `pink44`, `mewkiz192`), MP3 detection showed **no change** (`4/22` `SuspectedUpscaledLossy`, `1` `UpscaledFromCd`, `8` `Inconclusive`, `8` quiet solo-piano `AcousticNaturalRollOff`, `1` `MP3 V0` `VerifiedLossless`) and **0 false accusations**, while generalizing cleanly with improvements on genuine `soxr` 44.1 kHz downsamples (`+1`), low-sample-rate genuine files (`+1`), and Hi-Res upsampling (`2/2` `UpscaledHiRes`). Do not extrapolate DEV MP3 gains to unseen quiet solo-piano or broadband noise recordings beyond what was measured.

## Known Limitations

- **High-Bitrate Lossy Codecs Without a Hard Lowpass:** Modern `AAC` (`>= 192 kbps`), `Opus` (`64–192 kbps`, fullband `20–24 kHz`), `MP3 V0`, and `Vorbis q5` preserve upper-band energy without a brickwall cutoff and cannot be separated reliably from lossless masters by magnitude-only FFT.
- **MP3 `320 kbps` Near `20.1–20.2 kHz`:** Overlaps genuine `20 kHz` studio-lowpassed masters and is intentionally held as `Inconclusive` (manual inspection) rather than risking false accusations on authentic masters.
- **Quiet Solo-Piano 16-Bit MP3 Transcodes:** Very gentle acoustic recordings with negligible original harmonic energy above `14 kHz` before lossy encoding can remain `AcousticNaturalRollOff` under magnitude-only FFT (`8` HOLDOUT solo-piano MP3 tracks).
- **Linear-Interpolated Uncorrelated Pink Noise:** Naive linear upsampling of uncorrelated broadband random noise yields low Pearson mirror correlation (`r ≈ 0.12–0.17`) because random noise has no deterministic mirror contour across `22.05 kHz`.
- **Window-Position Sensitivity:** On tracks `>= 10 s`, the main 32-window FFT analyzes a single contiguous block around the loudest RMS probe point. Under `0.10 s` to `0.50 s` window shifts on the DEV set, the measured any-perturbation verdict flip rate is **`22%` (`22/100` files)**, with **`21/22` flips occurring on tracks `>= 10 s`** (`< 10 s` short clips dropped to `2.6%`, `1/39`, after 8-segment spreading).
- **1-Bit DSD Analysis:** DSD (`.dsf`) files are not decimated to PCM inside the inspector and return `Inconclusive` with a labeled representative curve (`IsSyntheticSpectrum = true`).
- **32-Bit Integer PCM Badge Label (Tracked for `v2.0.3`):** 32-bit integer FLAC files decode cleanly to 32-bit integer PCM, but the UI format badge currently maps `>= 32-bit` streams to `BitDepth.Bit32Float` (`"32-bit float"`).
- **Mixed EN/ID UI Labels & Non-Virtualized Detail Views:** Unchanged from v2.0.1 (`App.xaml` defaults to `Strings.id.xaml`; secondary detail views render in outer `ScrollViewer`s while primary lists are virtualized).
